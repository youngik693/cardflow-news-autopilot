# 출처·레퍼런스·이용 정책

기준일: 2026-10-21. 제작 헌법의 운영 부속 문서. 매체 이용 허가를 대신하지 않는다.

## 실제 확인 결과

| 대상 | 확인 내용 | 현재 운영 결정 |
| --- | --- | --- |
| FT Developer Programme | API별 허용 목적·라이선스를 따라야 한다. FT 상품을 대체하는 이용을 제한하고 제휴·보증 오인을 금지한다. 일반 약관의 일부 상업화 허용만으로 모든 재배포가 허용되는 것은 아니다. | 우리 계정의 라이선스가 확인되지 않았으므로 FT API 상업 재배포를 승인 상태로 두지 않는다. |
| FT Attribution Guidelines | 라이선스 이용에 적용되는 출처·브랜드 표기 조건이 있고 원문 복사·웹 재배포를 제한한다. | 매체 로고·‘Used under licence’ 표기를 권한 없이 붙이지 않는다. 실제 허용 범위를 먼저 확인한다. |
| NYT 공식 개발자 저장소 | API 명세와 별도 API 약관·출처 표기 안내가 존재한다. 이번 조사에서 현행 약관 본문은 접근 실패했다. | 무료 상업 이용 가능하다고 결론내리지 않는다. 현재 조건 확인 전에는 상업 자동 수집·재배포 소스로 활성화하지 않는다. |
| 미국 저작권청 FAQ | 공정이용은 상황에 따라 판단되며 일정 단어 수·비율을 쓰면 항상 허용된다는 규칙이 없다. | 출처 표시나 짧은 분량만으로 적법성을 자동 판정하지 않는다. 한국 운영에 적용될 조건도 별도로 확인한다. |

## 확보 경로

1. 기업 IR·공시, 정부·공공 통계, 공개 연구·발표 등에서 사실을 확인하고 자료별 이용 조건을 확인한다. 공개 자료라고 모두 같은 허용 범위를 갖는 것은 아니다.
2. 상업 가공·재배포가 허용된 오픈 라이선스 자료는 표시·변경 고지 등의 조건을 지킨다. NC·ND 등 제한을 구분한다.
3. 매체 API는 실제 이용 플랜·AI 처리·저장·캡션·SNS·유료 상품·이미지 범위를 각각 확인한다. 필요하면 권한 있는 라이선스를 확보한다. 유료 계약은 사용자 승인 없이 체결하지 않는다.
4. 사용이 제한된 매체의 표현·독점 분석을 돌려 쓰는 대신, 독립된 1차 자료로 사실을 재검증하고 직접 분석한다. 원문 접근·약관 제한을 다른 경로로 우회하지 않는다.
5. 인용 가능성은 목적·필요성·분량·적용 법과 계약 조건을 검토한다. 이 문서가 특정 인용의 합법성을 보장하지 않는다.

출처명은 실제 참고한 자료에만 붙인다. 기사 복제가 아닌 독자적인 조사·연결·설명·시각화가 우리 판매물의 중심이어야 한다.

## 출처 표시 형식

- 카드: ‘근거: 기관·매체명 / 자료 날짜 · 확인 시각(KST)’와 자료사진 크레딧.
- 캡션·근거 페이지: 저자, 제목, 발표일·수정일, 원문 URL, 어떤 주장을 지지하는지, 자체 해석·조건부 전망의 구분.
- 내부 기록: 접근 범위, 정책 URL·확인일, 라이선스 증빙·허용 범위. 키·토큰·개인 정보는 저장소에 공개하지 않는다.
- FT·NYT는 형식 예시이며 모든 카드에 공통으로 붙이는 배지가 아니다.
